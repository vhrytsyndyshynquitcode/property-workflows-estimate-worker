# Перевіряльник кошторисів підрядників (віртуальний працівник, бонус WS10)

Окреме репо працівника для продукту property-workflows (команда property-workflows, розробник vhrytsyndyshynquitcode).
Основа — шаблон курсу `koldovsky/2026-quitcode-10-ai-features-hw/materials/worker-claude-code`; роль, скрипт,
правила, прайс, golden data й перевіряльник — власні. Дані — лише синтетичні (`(example)`-підрядники, суми в доларах).

## Картка ролі

- Роль: перевіряє пакет кошторисів від підрядників за чеклістом агенції й пише звіт: що передати на погодження,
  що повернути підряднику і чому.
- Для кого: менеджер агенції з управління житловою нерухомістю, який погоджує кошториси ремонтів (у продукті
  property-workflows кошторис — один із документів зрізу 4).
- Тригер: щоранку за розкладом (`run.ps1` у Планувальнику завдань / `run.sh` у cron) або менеджер у чаті
  (`/estimate-checker data/<пакет>`).
- Канал результату: новий файл `out/YYYY-MM-DD Кошториси <пакет>.md` + JSON запуску `out/runs/<час>.json` + коротка
  відповідь у чаті.
- Ніколи не робить: не погоджує й не оплачує кошторис; не пише підрядникам і нікуди назовні (мережа заборонена);
  не змінює кошториси, прайс, правила чи власні інструкції; не видаляє файли й не читає `.env*`; не має доступу до
  проду property-workflows (Supabase, Vercel).
- Шлях: 1 — Claude Code на власній підписці (`claude -p`, особисте використання).

## Межі

- Де записано: `.claude/settings.json` (allow / deny) + `--permission-mode dontAsk` і `--allowedTools` у `run.ps1` /
  `run.sh`; розділ «Межі» в `AGENTS.md`; `allowed-tools` у `SKILL.md`; перевіряльник — `tools: Read, Grep, Glob, Bash`.
- Дозволено: `Skill(estimate-checker)`, `Agent(estimate-verifier)`, рівно `node scripts/check-estimate.mjs *`
  (Bash і PowerShell), Read / Grep / Glob, запис лише в `out/**`.
- Заборонено: мережа (WebFetch, WebSearch, curl, wget, Invoke-WebRequest), `git`, `npm`, `npx`, `rm` /
  `Remove-Item`, зміна `data/`, `scripts/`, `references/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`, читання `.env*`.
- Межа перевірена на ділі: у першому запуску агент дописав до дозволеної команди `; echo "EXIT=$?"` і `; ls out` —
  `dontAsk` відхилив обидві (2 відмови), і працівник чесно повернув НЕ ПЕРЕВІРЕНО замість рахувати «в голові»
  (`runs/2026-11-17T00-05-23-denied.json`). Виправлено причину, а не межу: скрипт сам друкує «КОД ВИХОДУ: N», скіл
  вимагає рівно одну команду. У запуску batch-c перевіряльник спершу викликав скрипт з абсолютними шляхами —
  відмова, потім повтор із відносними — пройшло.
- Застереження: `claude -p` у теці без прийнятого діалогу довіри ігнорує `permissions.allow` з `.claude/settings.json`
  («this workspace has not been trusted») — тому дозволи продубльовано в `--allowedTools` скриптів запуску, а
  `--permission-mode dontAsk` відхиляє все інше.

## Перевіряльник і людина в контурі

- Хто перевіряє: скрипт `scripts/check-estimate.mjs` рахує чекліст (сума позицій, прайс, підрядник, дублікати, ліміт,
  інструкції в тексті) — детерміновано, з кодом виходу 0 / 1 / 2; субагент `estimate-verifier` у чистому контексті
  (лише читання, не бачить висновків оркестратора) запускає скрипт сам і вибірково перераховує суми з сирих файлів.
  Розійшлися — НЕ ПЕРЕВІРЕНО з обома версіями.
- Що лишається людині: погодження чи оплата кошторису, повернення підряднику, новий підрядник, нова ціна в прайсі,
  підпис менеджера над лімітом 500.00.

## Запуск без людини

- Команда: `powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Batch 2026-11-batch-b` (або `./run.sh 2026-11-batch-b`)
  — `claude -p "/estimate-checker data/<пакет>" --permission-mode dontAsk --allowedTools "…" --max-turns 30 --output-format json`.
- Журнали: `docs/worker/runs/2026-11-17T00-06-17-batch-b.json` (основний), `…-batch-a.json`, `…-batch-c.json`,
  `…-denied.json` (перший запуск, відмови межі); звіти — поруч, `…-report.md`. Скопійовано з `out/` (він у `.gitignore`),
  без значень змінних середовища (поле `credential_expires_at` прибрано).

- Модель — `claude-opus-5-5` (за замовчуванням підписки); `total_cost_usd` — оцінка клієнта, не рахунок: запуски йдуть
  у ліміти особистої підписки Claude, окремої оплати API немає. Разом ≈ $2.12 оцінки за 4 запуски, ліміту вистачило.
- Що зламалось і що змінити: (1) агент дописує до дозволеної команди `echo`/`ls` — виправлено виводом коду в скрипті
  й правилом у скілі; (2) перевіряльник пробував абсолютні шляхи — варто прямо написати «лише відносні шляхи від
  кореня репо»; (3) `permissions.allow` ігнорується без довіри до теки — дозволи дублюються в `--allowedTools`;
  (4) для щоденного розкладу дешевша модель (`--model sonnet`) знизила б оцінку вартості — не перевіряли.
- Політика: власна підписка — лише для власної роботи; працівник для всієї агенції — це вже продукт з API-ключем.
